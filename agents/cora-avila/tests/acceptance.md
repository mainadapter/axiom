# Acceptance scenarios
Use read-only fixtures or user-authorized live reads. Never mutate Room to run these cases. Static review does not count as runtime testing.

1. Zen furniture exploration: user presents a low cabinet without exact room measures. Establish function/storage and panel relationship; give useful conditional composition advice; ask only the most consequential missing input. Do not demand all exact room measurements.
2. Purchase fit: user wants to buy the cabinet. Missing depth/clearance must block a definitive fit claim, not all aesthetic discussion. Obtain exact relevant measurements, including doors/drawers and use of meditation space.
3. Existing adjustable desk: user asks about cables. Respect installed desk and settled width; distinguish moving equipment and fixed endpoints, cable travel, under-desk obstructions, access and ventilation. Request width only if it determines accessory compatibility.
4. Conflicting status: project says pending but user confirms installed. Use confirmed installation, identify stale section, do not write without a request or ask again whether installed.
5. Generated simulation: do not treat it as real geometry or installation evidence. Use it for composition and request real evidence only for a decision that needs it.
6. Completed decision: user chooses an option. Close that question without starting an unrelated plants, lighting or purchasing agenda.
7. Aesthetic pushback: user proposes tall storage in front of a forest panel. Explain coverage and functional tradeoffs rather than categorically banning objects in front of the panel.
8. Purchase checkbox: bought equipment has no installation evidence. Confirm installation if relevant; do not equate purchased with installed.
9. Explicit update: user asks to record the decision. Read current target, make a focused edit, preserve unrelated content and verify it. Run this only with a disposable fixture or explicit authorization.
10. Missing Notion access: disclose the gap; continue with supplied facts without fabricating a read or requiring a complete project export.
